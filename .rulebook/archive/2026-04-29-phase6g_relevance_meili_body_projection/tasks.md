## 1. Lane projection — kind-aware text precedence
- [x] 1.1 Replace the fixed `summary > title > body` chain in `MeiliKeywordLane::project` (`crates/cortex-api/src/meili_lane.rs`) with a kind-aware match: artifact / law_violation prefer `body > summary > title`; decisions / analyses / memories keep `summary > title > body`; turns / tool_calls / agent_calls use `summary > body > title`; default falls back to today's chain. Implemented as `projection_chain(kind, &summary, &title, &body) -> [&Option<String>; 3]` returning slot references, then `.iter().find_map(...)` picks the first non-empty — allocation-free hot path.
- [x] 1.2 Add a `tracing::debug!` when the projected body exceeds the local `PROJECTED_BODY_DEBUG_BYTES` threshold (`4 * 1024`, mirrors `cortex_workers::fulltext::OVERSIZE_BODY_BYTES`). Stamps `doc_id`, `kind`, byte count, and the threshold so operators can flag oversized chunks without forcing per-snippet clamping in the lane (the orchestrator's existing trim ladder enforces the user-facing cap). Threshold is a private const because the API crate intentionally does not depend on the workers crate.
