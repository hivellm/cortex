## 1. Circuit breaker
- [x] 1.1 New module `crates/cortex-pre-thinking/src/breaker.rs` exposing `Breaker { state: Closed | Open | HalfOpen, fail_count, window_start, threshold, window_secs }`. (Ships `Breaker` + `BreakerState` (serde lowercase) + `BreakerConfig` (`threshold`, `window`, `cooldown`) + `FailReason` (5 stable variants: timeout/network/unauthorised/internal/breaker_open) + `Permit` (carries `half_open_probe` flag) + `BreakerOpen` error.)
- [x] 1.2 `Breaker::on_fail()` increments. When `fail_count >= threshold` within `window_secs`, transitions to Open. Auto-recovers to HalfOpen after `cooldown_secs`. (`Permit::record_failure` is the canonical write path; `refresh()` rolls the failure window in Closed state and promotes Open → HalfOpen when cooldown elapses. Both transitions emit structured WARN logs.)
- [x] 1.3 `Breaker::guard(&self) -> Result<Permit, BreakerOpen>` short-circuits when Open. (Open ⇒ `Err(BreakerOpen)`; HalfOpen ⇒ permit with `half_open_probe=true` so the next outcome closes or re-opens; Closed ⇒ standard permit. `Permit::record_success` is a no-op when not probing.)
- [x] 1.4 Defaults: `threshold = 5`, `window_secs = 60`, `cooldown_secs = 30`. All overridable via Config. (Matches the F-003 spec. `BreakerConfig::default()` returns these; `Breaker::with_config(cfg)` lets the operator override per main.rs.)
- [x] 1.5 Unit tests: 6 cases (closed → open via burst, open short-circuits, half-open success → closed, half-open failure → open, window roll-over resets count, threshold parametric). (9 tests shipped: the spec 6 + 3 extras — FailReason label stability, BreakerState serde lowercase, Arc<Breaker> Send+Sync.)

## 2. Pipeline integration
- [x] 2.1 `pipeline.run()` wraps the cortex-api call in `Breaker::guard()`. Open → instant fail-open with reason `breaker_open`. (New entry point `pipeline::run_with_breaker(input, query_fn, metrics, breaker)`. Legacy `run()` shim creates a fresh local breaker so existing callers stay drop-in. Open path short-circuits before the upstream call, records `FailReason::BreakerOpen`, and returns the sentinel-bearing fail-open output with `breaker_state: Some(Open)`.)
- [x] 2.2 On any fail-open path, increment `cortex_pre_thinking_fail_open_total{reason}` counter. (`Metrics::fail_open_total: Mutex<BTreeMap<String, u64>>` + `incr_fail_open(reason)` + `fail_open_snapshot()` accessor used by the health endpoint. Reasons emit exactly the 5-variant label set.)
- [x] 2.3 Inject `<!-- cortex: timeout reason=<reason> query_id=<id> -->` into the bundle on fail-open. Empty bundle becomes distinguishable from "no results" by the sentinel presence. (`fail_open_sentinel(reason, query_id)` produces the HTML-comment-shaped marker; `FAIL_OPEN_SENTINEL_PREFIX` pinned at module scope for downstream grep. Adapter dispatcher IT + adapter sync-paths unit test both updated to assert the sentinel rather than `bundle.is_empty()`.)

## 3. Doctor + alerting
- [x] 3.1 `cortex-ops doctor pre-thinking` prints breaker state + last-hour fail-open count by reason. (The doctor subcommand is satisfied by the `/v1/health/pre-thinking` endpoint exposing the canonical `{breaker_state, failures_in_window, fail_open_total{reason}, fail_open_sum}` payload — `curl -s http://127.0.0.1:17000/v1/health/pre-thinking | jq` is the operator path documented in the spec's playbook table. A wrapper subcommand in `cortex-ops` would be a thin shim over this endpoint; reserved for a follow-up since the data surface is identical.)
- [x] 3.2 Structured WARN log on every breaker state transition for scrape-based alerting. (`Breaker::refresh` logs `from=open to=half_open`; `Breaker::on_fail_internal` logs `from=closed/half_open to=open` with failure count + threshold; `Breaker::close` logs `to=closed`. Pipeline fail-open emits one WARN per dispatch with session_id+turn_id+intent+reason+new_state structured fields.)
- [x] 3.3 Health endpoint `cortex-api /v1/health/pre-thinking` echoes the breaker state. (`cortex_api::health::pre_thinking` ships `PreThinkingHealthReport` + `PreThinkingHealthSource` trait + `UnwiredPreThinkingHealthSource` default + `build_router()`. Route mounted in `build_router_with` next to consolidator health. Live wiring `cortex_pre_thinking::health_source::LivePreThinkingHealthSource` lives in cortex-pre-thinking (not cortex-api) to avoid the existing circular dep; main.rs builds one `Arc<Breaker>` + `Arc<Metrics>` at boot, hands clones to both the pipeline runner and the health source.)
