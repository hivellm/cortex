## 3. Doctor check
- [x] 3.1 New `Command::DoctorMeiliIndexes` in [`crates/cortex-cli/src/bin/cortex-ops.rs`](../../../crates/cortex-cli/src/bin/cortex-ops.rs) with `--meili-url` / `--master-key` / `--json` flags. Handler in [`crates/cortex-cli/src/bin/cortex-ops/doctor.rs::doctor_meili_indexes`](../../../crates/cortex-cli/src/bin/cortex-ops/doctor.rs) walks `cortex_storage::fulltext::INDEXES`, GETs `{meili}/indexes/{name}/settings` per entry, and compares the declared `searchableAttributes` / `filterableAttributes` / `sortableAttributes` against the live values as **sorted sets** (Meili reorders these on read; only set membership matters for these three keys). Reports per-index status `ok` / `drift` / `missing` / `error` with per-attribute `declared` vs `live` arrays in `--json` mode.
- [x] 3.2 Exit code `0` when every entry is `ok` and there is no transport error; `2` on any `drift` / `missing` / `error` / network failure. `MeiliDriftReport::has_drift()` short-circuits on transport-level failure so an unreachable backend does not silently report green.
- [x] 3.3 Live smoke against the running Meili (port 17004, master key `cortex-dev-master-key`) surfaced 10 `missing` indexes (never created) + 2 `drift` indexes (`cortex_decisions`, `cortex_laws` — settings PATCH was never applied) + correct `missing` flag on the two new `cortex_consolidations` / `cortex_topic_cards` entries — exactly the operational state the doctor was meant to surface. Exit code `2` confirms the gate works. 7 unit tests in `doctor::meili_drift_tests` (set-equality match, single-attribute drift, multi-attribute drift, declared-empty/live-populated, error vs missing classification, report short-circuit when any non-ok, report ok when every entry ok). `cargo test -p cortex-cli --bin cortex-ops doctor::meili_drift_tests` 7/7 green.
