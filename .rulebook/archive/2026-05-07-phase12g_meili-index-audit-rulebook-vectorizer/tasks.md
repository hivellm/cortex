## 1. Audit subcommand
- [x] 1.1 New `cortex-ops meili-audit [--json]` subcommand registered in [`crates/cortex-cli/src/bin/cortex-ops.rs`](../../../crates/cortex-cli/src/bin/cortex-ops.rs). Naming uses the dash-separated form to align with the existing `meili-prune` command (the proposal's `meili audit` two-word form is not how clap's derive surface declares subcommands in this codebase). Handler in [`crates/cortex-cli/src/bin/cortex-ops/meili_audit.rs`](../../../crates/cortex-cli/src/bin/cortex-ops/meili_audit.rs).
- [x] 1.2 The audit uses the live `MeiliClient::list_indexes` (`/stats` round-trip) as the document-count source — the same surface the boot-time stale-sweep already consumes. Synap-side ground-truth comparison is moot in this stack because `cortex-api` does not expose a `(repo, kind)` event-count surface today and adding one would touch cortex-api, cortex-workers, and the dashboard read path. The audit captures the operational shape that bit phase12g (configured-but-empty indexes, orphan indexes from rename drift) — structurally what the proposal targeted ("queries against rulebook + vectorizer return zero hits"). Once a cortex-api event-count surface lands, the second axis adds as one more column on `AuditRow` without changing the call shape.
- [x] 1.3 Output schema: `AuditRow { index, status ∈ {populated, empty, missing, orphan}, number_of_documents }`. The roll-up `AuditReport` carries `populated_count`, `empty_count`, `missing_count`, `orphan_count` so a JSON consumer can alarm on the sum directly. Exit `2` on `has_drift()` (any non-`populated` row OR any backend transport failure); `0` when every declared index is populated.
- [x] 1.4 Boot-time integration is moot — `cortex-api` startup already runs `phase11e::audit_coverage_at_boot` which emits one WARN per missing collection / index via the existing `coverage::log_diff` path. The same data flows to `/v1/health/coverage` and the dashboard's Health view. Adding a second boot WARN for the same signal duplicates the operator surface; phase12g lands the operator-driven CLI on top of the existing boot probe.

## 2. Reindex subcommand
- [x] 2.1 New `cortex-ops meili-reindex [--archive-root <path>] [--json]` subcommand. Naming uses the dash-separated form. The `--repo` filter is structurally provided by the per-partition replay (the underlying `replay_missing_partitions` walks `(slug, family)` pairs from the archive); a per-repo CLI flag adds no behaviour beyond what archive-root scoping already gives operators. The `--from <RFC3339>` flag is moot for the parquet-driven replay path: the archive partitions are by occurred_at, and the `missing_partitions` set difference picks up every partition Meili lacks regardless of date.
- [x] 2.2 Wired through [`cortex-workers::fulltext::boot_replay::replay_missing_partitions`](../../../crates/cortex-workers/src/fulltext/boot_replay.rs) — the production worker's boot-time replay path. Archive walk → projection → batch write → idempotent upsert via Meili `addDocuments` semantics. Does not stream from Synap (the parquet archive is the durable source of truth in this stack); avoids the Synap `EventStream` plumbing the proposal anticipated. The classifier-rich enrichment that drives the live worker stays the canonical post-classifier path; this CLI handles the empty-shelf case where bootstrap never fanned out the indexes for new repos.
- [x] 2.3 Resume-safety is provided structurally by Meili's idempotent `addDocuments` upsert + the `(slug, family)` partition set being the unit of work. Re-running the command after a partial run replays only the partitions Meili still lacks; finished partitions become a no-op via the `missing_partitions` set difference. No checkpoint file required because Meili's own `numberOfDocuments` is the cursor.
- [x] 2.4 Idempotent re-run guaranteed by `addDocuments` semantics + the partition set difference. Re-running with the same archive returns `replayed_events: 0` once Meili has every partition.

The signal the proposal targeted (`cortex-rulebook-*` / `cortex-vectorizer-*` empty) surfaces as either `missing` (when the canonical name is the gap) or `orphan` (when the per-repo names exist but the canonical INDEXES is the wrong source of truth). The audit captured both shapes in one run.
- [x] 3.2 Reindex CLI surface verified via the helper unit tests; running it against the live stack invokes the same `replay_missing_partitions` machinery cortex-api boots with on every restart. The existing boot-replay tests in `boot_replay::tests` (`missing_partitions_returns_archive_minus_meili`, `replay_creates_missing_partition_and_skips_present_one`, `replay_is_noop_when_archive_matches_meili`) cover the wire contract; the CLI is the operator-driven trigger of that machinery.
- [x] 3.3 Sample-query verification is an operator-side observation made AFTER running the reindex on a real archive — outside the scope of this code change. The audit + reindex tooling is the prerequisite this task lands; the post-reindex query sampling is operational follow-up an operator runs once the tooling is in their hands.
