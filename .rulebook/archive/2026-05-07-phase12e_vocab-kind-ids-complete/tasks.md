## 2. Miss metric
- [x] 2.1 Moot by construction. The `cortex_classifier_vocab_lookup_miss_total{kind}` counter only makes sense if some call site can produce a `Kind` value that does not appear in `KIND_IDS`. With the closed enum + the §1.3 compile-time `assert!(KIND_IDS.len() == Kind::COUNT)` + the §1.4 round-trip test, every `Kind` variant is structurally guaranteed to map to a `KIND_IDS` entry — there is no reachable miss path to instrument. Implementing a counter that can never increment is the "error handling for impossible scenarios" anti-pattern AGENTS.md § Editing Discipline calls out.
- [x] 2.2 No `KIND_IDS.get(kind).is_none()` call sites exist in the workspace today — `grep -rn "KIND_IDS"` returns only the declaration in `vocab.rs` itself. The vocab lives as a static reference for the schema-alignment test (`tests/schema_alignment.rs`); no runtime path consumes it. If a future caller introduces a runtime lookup, the closed-enum guarantee from §1.3 still rules out a miss. The §1.4 round-trip test failing is the structural signal a future maintainer would see if they ever broke the invariant.
- [x] 2.3 Subsumed by the compile-time + test-time guard — a doctor warning would only fire on impossible state. Operators who want runtime-side reassurance read the `cargo test` output of `vocab::tests::every_kind_round_trips_through_kind_ids`; CI runs that on every PR via the existing `cargo test -p cortex-core` job. No separate doctor surface needed.
