## 3. Resumable & idempotent
- [x] 3.1 Per-repo checkpoint entry written via `write_atomic` after each repo completes — already supported by `Checkpoint::repos: BTreeMap<String, RepoProgress>`; the orchestrator calls `write_atomic` after every repo iteration (success or failure)
- [x] 3.2 Bypass repos whose checkpoint reports `status = done` AND `last_git_ref` equals current `HEAD` — new `git::current_head_sha(repo_root) -> Option<String>` shells `git rev-parse HEAD`; `main.rs` bypasses repos whose checkpoint matches; `--force` overrides
- [x] 3.3 `--force` flag overrides the bypass; logs `info` per forced repo — `CliArgs::force: bool`; main logs `info` when the flag re-runs a done repo
- [x] 3.4 Ctrl-C between repos leaves checkpoint consistent; the next invocation resumes at the first not-done repo — already covered by the existing `install_ctrlc_handler` + per-iteration `write_atomic`; the new bypass-when-done check then bypasses every previously-done repo on resume
