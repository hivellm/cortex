# Proposal: phase30_continuity-loop-verification

## Why
Cortex's core value proposition is fixing the "/clear-amnesia" problem — a new session should be able to retrieve what a prior session learned or decided, without the operator re-explaining it. The individual pieces exist and are independently tested: session/topic/decision-trace consolidations (spec 27), `cortex_session_replay`, `cortex_active_work`, a Handoffs dashboard view (`gui/src/views/Handoffs.tsx`), and `cortex_capture_memory`. What is missing is end-to-end proof that a session-end consolidation is actually injected into the very next session's pre-thinking bundle — the pieces are unit- and component-tested, but the full loop from "session A ends and writes a consolidation" to "session B's `cortex_pre_thinking` call surfaces it" has never been exercised as a single test.

Separately, `cortex_active_work` (in-flight Rulebook tasks) exists as an on-demand MCP tool and can already be folded into a `cortex_pre_thinking` bundle via the phase13g grounding-section path (`GroundingSections::active_work` in `crates/cortex-pre-thinking/src/formatter.rs`), but nothing calls it automatically when a session starts. The `SessionStart` hook (`crates/cortex-adapter-claude-code/hooks/cortex-session-start.sh`) is a fire-and-forget notification shim today — it does not fetch or inject anything on its own. A new session therefore does not automatically know what was in progress unless the agent happens to issue a `cortex_pre_thinking` call with the right intent first.

## What Changes
- Add an integration test that exercises the full continuity loop: session A produces a consolidation, a fresh session B (same repo scope) calls `cortex_pre_thinking` with a related query, and the test asserts the consolidation from session A appears in session B's bundle.
- If that test fails, root-cause exactly where the loop breaks (embedding lag, wrong collection queried, pre-thinking renderer filtering it out, scope mismatch, etc.) and record the finding — the fix itself is out of scope for this task unless it is the active-work wiring below; anything else discovered becomes a follow-up Rulebook task per the deferred-items protocol.
- Wire `cortex_active_work` (or equivalent) into the session-start flow — the adapter's `SessionStart` hook and/or the pre-thinking bundle assembly path — so a new session automatically surfaces prior in-flight Rulebook tasks without the agent having to think to call the tool.
- Document the verified (or newly-fixed) continuity loop as an operator runbook under `docs/cortex/`, covering what to check if a user reports "the agent forgot what we just did."

## Impact
- Affected specs: `docs/specs/27-consolidation.md` (session/topic/decision-trace grains and their retrieval contract), `docs/specs/12-pre-thinking-injection.md` (bundle assembly, grounding sections), `docs/specs/10-claude-code-adapter.md` (`SessionStart` hook behavior); new spec module `continuity` added by this task.
- Affected code: `crates/cortex-pre-thinking/src/formatter.rs` (bundle assembly / grounding-section rendering), `crates/cortex-adapter-claude-code/hooks/cortex-session-start.sh` and its dispatcher (`crates/cortex-adapter-claude-code/src/dispatcher.rs`), `crates/cortex-api/src/active_work.rs` (`cortex_active_work`), `crates/cortex-mcp-server/src/tools.rs` (tool registration); new integration test; new `docs/cortex/` runbook.
- Breaking change: NO — this is verification plus an additive, backward-compatible wiring change (a session-start surface that was previously silent now emits a summary).
- User benefit: proves — or, if the loop is broken, surfaces and starts fixing — Cortex's central "don't lose institutional knowledge across a `/clear`" promise end-to-end, which is the reason the project exists. Related background: `docs/analysis/cortex/11-platform-vision-analysis.md` and `docs/specs/27-consolidation.md` (the consolidation-grain design this task verifies against).
