# Proposal: phase31_pre-thinking-audit-trail

## Why
Spec 12 (pre-thinking injection) is implemented and stamps every bundle with a `query_id` for auditability, but its audit story is only partial in practice. `cortex_audit` (backed by `AuditStore` in `crates/cortex-api/src/security/audit_store.rs`) returns the retrieval envelope for a single query, but that store is an in-memory FIFO ring buffer bounded at 1024 entries (`DEFAULT_STORE_CAPACITY`) — once that many `cortex_pre_thinking` calls happen (roughly 30 minutes of heavy traffic, per the store's own doc comment), older envelopes are gone forever. There is also no persisted, queryable trail connecting a `query_id` to what the agent actually did with the bundle in the following turn. Without this, there is no way to measure whether pre-thinking injection is actually helping agents make better decisions, or just adding noise and cost — this gap is called out directly in `docs/analysis/cortex/11-platform-vision-analysis.md`: "bundle content is ephemeral (not persisted for audit). Spec 12 promises a query_id trail — not yet implemented."

## What Changes
- Persist, for every `cortex_pre_thinking` call: `query_id`, a summary of the assembled bundle's sections/content, and the timestamp — durably, beyond the in-memory ring buffer's retention window. `crates/cortex-pre-thinking/src/formatter.rs::count_sections()` already computes a non-zero per-section count summary of a rendered bundle and is the natural starting point for what gets persisted.
- Where determinable from the session's subsequent turns (tool calls, file edits, decisions recorded), link the `query_id` to the downstream action(s) that followed it in the same session — a best-effort heuristic (e.g. "next N tool calls in this session after this query_id") is an acceptable first version.
- Expose this persisted trail in a new or extended dashboard view, so an operator can browse "what did Cortex tell the agent, and what did the agent do next?"
- Define and compute a "bundle utilization" heuristic (did any file/decision/law cited in the bundle get referenced again in the following turns?) and surface it as a metric, to start building evidence for whether pre-thinking is actually helping.

## Impact
- Affected specs: `docs/specs/12-pre-thinking-injection.md` (extends the existing `query_id`/audit-trail promise with a durability and downstream-linkage contract); new spec module `pre-thinking` added by this task.
- Affected code: `crates/cortex-api/src/security/audit_store.rs` (currently an in-memory bounded ring buffer — this task needs a durable store, e.g. via the existing Parquet archive pattern in `crates/cortex-storage/src/archive.rs` or the SQLite checkpoint pattern in `crates/cortex-storage/src/metadata.rs`, for the trail to survive beyond 1024 entries), `crates/cortex-api/src/service.rs` (where `AuditStore` is currently constructed and wired), `crates/cortex-api/src/http.rs` (`GET /v1/audit/{query_id}`), `crates/cortex-mcp-server/src/tools.rs` (`cortex_audit` tool), `crates/cortex-pre-thinking/src/formatter.rs` (`count_sections()` bundle summary), and the dashboard (`gui/` — no audit-focused view exists today; `gui/src/views/Handoffs.tsx` is the closest structural sibling).
- Breaking change: NO — additive observability; the existing in-memory ring buffer behavior and the `cortex_audit` tool's current response shape are preserved, with durability added underneath.
- User benefit: turns "we assume pre-thinking helps" into a measurable claim, and gives operators a way to debug low-value or noisy bundles instead of assuming they help.
