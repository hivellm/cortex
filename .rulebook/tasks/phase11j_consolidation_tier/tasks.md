## 2. cortex-consolidator crate

- [x] 2.1 New crate `crates/cortex-consolidator/` shipped + added to workspace members. - [x] 2.2 Three real prompt templates land under `crates/cortex-consolidator/templates/` (`session.md`, `topic.md`, `decision_trace.md`). Each has a header section declaring inputs (`{{key}}` slots the producer fills), a "Source" block, and an output-contract block pinning the JSON shape (`title` / `summary_markdown` / `takeaways`). `templates.rs` resolves them via `Template::for_grain` and renders via plain `{{key}}` substitution; per-grain `max_output_bytes = 2_000` and `takeaways_count = 3 / 5 / 7` for Session / Topic / DecisionTrace match the proposal. 3 unit tests pin distinctness across grains, the takeaways-count contract, and the render fallback (untouched slots stay literal so a typo surfaces).
- [x] 2.3 `summariser.rs` ships the abstract `Summariser` trait + the live `AnthropicSummariser` impl that hits `POST {base}/v1/messages` (Anthropic Messages API) with `x-api-key` + `anthropic-version` headers and parses the `usage.input_tokens` / `usage.output_tokens` block. Pricing constants `HAIKU45_*` / `OPUS47_*` (USD micro-cents per 1k tokens) drive the `cost_cents()` helper that rounds half-up. Errors split into `RateLimited { retry_after_ms }` (429 → orchestrator backs off), `UpstreamUnavailable` (5xx → orchestrator retries once + falls back), `Upstream { status, body }` (other 4xx → terminal), `Transport`, `CostCeiling`. 4 unit tests pin cost scaling (Opus 1M+1M tokens = 9 000 cents = $90), micro-cent rounding edge case, base-URL override, and `SummariserKind` snake-case serde round-trip. `ANTHROPIC_API_URL` env var overrides the base for staging deployments.
- [x] 2.4 `producer/session.rs` ships the full pipeline: `SessionInput` (envelope vec + repo + session_id) → `render_prompt` (substitutes `session_id`/`repo`/`started_at`/`ended_at`/`turn_count`/`outcome_summary`/`source_turns` slots) → `Summariser::summarise` → `parse_model_response` (strips ```json``` code fences then deserialises into `{title, summary_markdown, takeaways}`) → builds `ConsolidationPayload` with grain=Session, scope=SessionId, model = summariser.kind.model_id, depth derived from kind, outcome_distribution from `payload.outcome` counts, temporal_span from earliest/latest `occurred_at`, source_event_ids clipped at the §1 inline cap with `source_event_count` holding the unclipped total → runs `validate_produced` (forwards to §1.5 cross-field rules) → returns `ProducedConsolidation { payload, cost_cents }`. 9 unit tests pin: empty-input rejection, temporal-bounds min/max, outcome-distribution counter, prompt rendering substitution, code-fence stripping (json + plain + raw), model-response parse error on missing fields, end-to-end produce pipeline against a stub summariser, source-id clip-at-cap with preserved count, summary-below-floor rejection.
- [x] 2.5 `producer/topic.rs` ships the topic-cluster pipeline. `ClusterSession` carries `session_id` / `start_ms` / `end_ms` / `outcome_distribution` / `one_line_digest`; `TopicCluster` is `{ label, repo, sessions }`. `MIN_CLUSTER_SIZE = 3` matches the proposal. `aggregate_outcomes()` sums per-session counts; `temporal_bounds_ms()` picks min start / max end. `produce(&cluster, &summariser)` renders the topic template (`topic_label` / `repo` / `cluster_size` / `temporal_span` / `outcome_distribution` / `source_sessions` slots), parses the `{title, summary_markdown, takeaways}` response, builds a `Kind::Consolidation` payload with grain=Topic, scope=Topic(label), repos=[cluster.repo], tags=[cluster.label], outcome_distribution from the aggregate. HDBSCAN clustering itself stays the orchestrator's responsibility (§2.7) so the algorithm is swappable; the producer only takes pre-clustered input. 5 unit tests pin: undersized-cluster rejection, threshold acceptance, aggregate-outcomes summing, temporal-bounds min/max, end-to-end produce against a stub summariser.
- [x] 2.6 `producer/decision_trace.rs` ships the decision-chain pipeline. `MAX_HOPS = 16` matches the proposal. `DecisionTraceInput` carries `decision: Envelope` (must be Kind::Decision; rejected otherwise) + `chain: Vec<Envelope>` (root → decision.parent, capped at MAX_HOPS) + `repo`. `decision_id()` reads `payload.decision_id` with fallback to `event_id`. `render_prompt` substitutes `decision_id` / `decision_title` / `decision_status` / `repo` / `decided_at` / `chain_hops` / `source_chain` slots and emits the chain in oldest-first order. `produce(&input, &summariser)` runs the same parse → build → validate pipeline; payload sets grain=DecisionTrace, scope=DecisionId(_), depth=Deep when summariser kind is Opus47. source_event_ids covers chain + decision (+1). 4 unit tests pin: chain over MAX_HOPS rejection, non-Decision trigger rejection, decision_id fallback, end-to-end produce with Opus depth + DecisionId scope.
- [x] 2.7 `orchestrator.rs` ships three async dispatchers — `run_session(&SessionInput)`, `run_topic(&TopicCluster)`, `run_decision_trace(&DecisionTraceInput)` — each maps the trigger to a `ProducerSelection`, gates against the budget via the conservative per-kind estimate (100 cents Haiku / 4 000 cents Opus), invokes the matching producer, and stamps the realised cost into the per-grain `CostLedger` bucket. `with_budget(CostBudget)` builder method overrides the default $1 000/month cap. `gate_budget` returns `ProducerError::Summariser(SummariserError::CostCeiling)` when the estimate would breach the cap so the orchestrator never emits a charge that breaks the operator budget. - [x] 2.8 `cost_telemetry.rs` ships `GrainCost` (`consolidations` count + `cost_cents` total + `mean_cost_cents()`), `CostLedger` (per-grain `BTreeMap` keyed by snake-case grain label + `total_cents`; `record(grain_label, cost_cents)` + `reset()`), and `CostBudget` (default $1 000/month = 100 000 cents) with `remaining_cents()` + `can_afford(est_cents)`.
