## 1. Schema additions
- [x] 1.1 Add `Symbol` node label and `DEFINES` edge type to `cortex-graph::schema` — `SCHEMA_STATEMENTS` gains a UNIQUE constraint on `Symbol.natural_key` and a secondary index on `(s.repo, s.name)` for fast "where is symbol X defined?" lookups
- [x] 1.2 `Symbol` natural key in `identity.rs`: `(repo, language, qualified_name)` — `symbol_natural_key()` joins with `|` mirroring `artifact_natural_key`. The mapper folds the artifact path into `qualified_name` when the chunker emits a bare name (no FQN concept in the source language) so two `parse()` functions in different files hash distinct
- [x] 1.3 Property defaults: `name` (string, required), `language` (string, required), `signature` (string, optional), `kind` (string: `function|struct|class|trait|enum|other`) — partial-by-design: `name`, `language`, `repo`, `qualified_name` ship today; `signature` and `kind` are not in scope for this PR because the embedder's `Chunk.metadata` only surfaces `symbol` + `language` at chunk-time, not the structural classification this item names. The Symbol node carries everything the chunker actually emits today; richer metadata waits on the chunker emitting it

## 2. Mapper — emit symbol patches
- [x] 2.1 In `mapper.rs`, for every artifact-chunk event with `source == "code"` and a non-empty `symbol` field, produce a `Patch::MergeNode(Symbol)` and a `Patch::MergeEdge(Symbol -> Artifact, DEFINES)` — `emit_symbol_patches` runs `CodeChunker::chunk()` against `Kind::Artifact` events and emits `(Symbol, DEFINES → Artifact)` per top-level declaration the chunker recognises
- [x] 2.2 Tolerate events whose `symbol` is missing — they become Artifact-only patches as before; no error — chunker errors / unrecognised languages / empty bodies all return `Vec::new()`; the mapper continues without logging
- [x] 2.3 Coalesce duplicate symbols within a single batch — already handled by `coalescer.rs`; assert the test path covers it — intra-event dedupe added explicitly via `BTreeSet<String>` keyed on the natural key (`duplicate_symbol_within_one_event_collapses_to_a_single_node`); the across-batch coalescer keeps doing its job unchanged

## 3. Cypher templates
- [x] 3.1 `render_symbol_merge` produces `MERGE (s:Symbol {repo, language, qname}) ON CREATE SET ...` honoring the project's identity convention — `cypher/node_symbol.cypher`: `UNWIND $rows AS row MERGE (n:Symbol { natural_key: row.key }) SET n += row.props` (matches the convention every other node template uses; `natural_key` is composed by the mapper from `(repo, language, qualified_name)`)
- [x] 3.2 `render_defines_merge` produces `MATCH (s:Symbol ...), (a:Artifact ...) MERGE (s)-[:DEFINES]->(a)` with the same MATCH-fail-tolerance the existing edge MERGEs use — `cypher/edge_symbol__defines__artifact.cypher`: `UNWIND $rows AS row MERGE (a:Symbol { natural_key: row.from }) MERGE (b:Artifact { natural_key: row.to }) MERGE (a)-[r:DEFINES]->(b) SET r += row.props` (silent endpoint MERGE keeps replay idempotent without crashing)
- [x] 3.3 Register both templates in `CypherTemplates` — `REQUIRED_TEMPLATES` gains `"node_symbol"` and `"edge_symbol__defines__artifact"`; the existing `shipped_cypher_dir_satisfies_required_set` test guards both files against accidental deletion
