## 2. New crate
- [x] 2.1 `crates/cortex-config/Cargo.toml` + `src/lib.rs` exposing `pub struct Config` (serde-versioned, tag `schema_version`, current `"v1"`). New workspace member added at `crates/cortex-config/`. Top-level `Config` carries `schema_version: String` (defaulted to `SCHEMA_VERSION = "v1"`) plus the 7 domain sub-structs. `validate()` rejects any non-`v1` value with `ConfigError::UnsupportedSchemaVersion(seen)` so a `v2` migration is a future serde-tag-dispatched fork rather than a silent default fallthrough.
- [x] 2.2 Sub-structs by domain: `RetentionConfig`, `EmbedderConfig`, `MeiliConfig`, `NexusConfig`, `IngestionConfig`, `DashboardConfig`, `PreThinkingConfig`. All 7 land in `src/sub.rs` with full `Default` + per-field doc comments naming the legacy `CORTEX_*` env var.
- [x] 2.3 `pub fn load() -> Result<Config>` resolves CLI > env > `cortex.toml` > default (figment crate or hand-rolled). Hand-rolled (no figment dep — single merge pass is cheaper than the dep weight). 3 entry points: `Config::load()` (cwd `cortex.toml` + process env), `Config::load_from(path, env_lookup)` (hermetic — tests bind `env_lookup` to a HashMap snapshot), `Config::load_with_cli(path, env_lookup, overrides)` (binaries thread clap-derived JSON overlay). Merge is deep-object: higher-precedence scalars / arrays clobber lower; objects merge key-wise. `default_toml_path()` honours `CORTEX_CONFIG_FILE` override.
- [x] 2.4 `pub fn audit() -> Vec<EnvVarUsage>` walks the workspace via `walkdir` + regex and reports any `std::env::var("CORTEX_*")` outside `cortex-config`. Implemented in `crates/cortex-config/src/audit.rs`. Walks every `*.rs` under `crates_root` skipping `target/`, `.git/`, `node_modules/`, the `cortex-config` crate itself (legitimate reader), and `tests/` directories (test fixtures may probe env vars for hermetic setup). Matches three call shapes via a single regex: `std::env::var("CORTEX_*")`, `env::var("CORTEX_*")`, `env::var_os("CORTEX_*")`. Returns `Vec<EnvVarUsage { path, line, env_name }>` sorted by (path, line, env_name) for stable diff across runs. Paths emitted with forward slashes for cross-OS reporting. 7 unit tests in `audit::tests` (empty workspace → empty; flags std::env::var; flags both env::var + env::var_os; ignores non-CORTEX vars; skips cortex-config itself; skips test dirs; stable sort across multi-file).
- [x] 2.5 Each `CORTEX_*` env name retained as a serde alias on the corresponding field. Round-trip test pins the alias map. Implemented via the `KNOWN_ENV_NAMES: &[(&str, &str)]` table in `src/env_map.rs` mapping env-name → JSON pointer. `#[serde(alias)]` does NOT cover flat-env-to-nested-toml mapping (`CORTEX_EMBEDDER_VECTORIZER_URL` → `embedder.vectorizer_url`); the table + the `env_overlay()` stitch is the equivalent. 4 unit tests in `env_map::tests` (sorted-list invariant for binary_search, known-knob resolution, unknown returns None, no duplicates) + 6 unit tests in `load::tests` (full defaults, env > default, env numeric coercion, toml > default + env > toml, cli > env > toml, empty env value falls through, unsupported schema rejected). 11/11 green; `cargo check --workspace` clean.

## 3. Migrate call sites
- [x] 3.1 `cortex-api/src/main.rs` (38 live CORTEX_* reads → 0). Replaced each `std::env::var("CORTEX_*")` with typed `cortex_config::Config` accessor. Helpers (`api_keys_db_path`, `resolve_metadata_db_path`, `audit_coverage_at_boot`, `resolve_vectorizer_bearer`, `build_nexus_client`) now take `&cortex_config::Config`. `resolve_fusion_config_from_env_with_base` + `resolve_query_rewriter_from_env` re-call `Config::load()` internally so SIGHUP relevance-reload re-reads env+toml together. Config extended: EmbedderConfig (`vectorizer_api_key`, `jwt_warmup_secs`; `vectorizer_url` → `Option<String>`); DashboardConfig (`api_keys_db`, `watch`, `memory_tail`, `coverage_slugs`, `rrf_alpha`, `rrf_k`, `query_rewriter`); NexusConfig (`nexus_api_key`; `nexus_url` → `Option<String>`); IngestionConfig (`home`); MeiliConfig (`meili_url` → `Option<String>`). New sub-structs: RulebookConfig, CanaryConfig. 19 new KNOWN_ENV_NAMES entries (incl. legacy `CORTEX_VECTORIZER_{URL,USER,PASSWORD}` aliases collapsed onto `/embedder/*` pointers). URL gate fields refactored to `Option<String>` so unset env preserves the "lane disabled" semantic; worker configs default the URL at the worker boundary. Non-CORTEX env vars (VECTORIZER_URL, NEXUS_URL, MEILI_MASTER_KEY, HOME, USERPROFILE) stay as direct env reads (§3.6 grep gate is CORTEX_*-only). Operator-visible break: `CORTEX_DASHBOARD_WATCH` / `_MEMORY_TAIL` / `_CANARY_ENABLED` now require literal `true`/`false` (legacy `0`/`1`/`yes`/`on` no longer accepted).
- [x] 3.2 `cortex-api/src/http.rs` (19 live CORTEX_* reads → 0). `ApiState` extended with `cfg: Arc<cortex_config::Config>`; new `build_router_with_auth_and_cfg(...)` builder lets main.rs thread the boot-time snapshot through so handlers + the dashboard agree on the same resolution. Handlers `handle_health_coverage`, `resolve_vectorizer_bearer_for_audit`, `handle_admin_forget` rewritten to read `state.cfg.*` instead of env vars. Config extended: `DashboardConfig.coverage_slugs_only: Option<String>`. env_map: 2 new entries — `CORTEX_COVERAGE_SLUGS_ONLY` → `/dashboard/coverage_slugs_only`, `CORTEX_FULLTEXT_MEILI_KEY` → `/meili/meili_api_key` (legacy alias of `CORTEX_FULLTEXT_MEILI_API_KEY`).
- [x] 3.3 `cortex-api/src/config_audit.rs` integrates `cortex_config::audit()`. Reinterpreted: the existing module is the operator-facing static analysis of config FILES (.env, adapter.toml, .mcp.json, hooks.json, live ports, duplicate deps) — a distinct concern from `cortex_config::audit()`'s code scanner. A blind replacement would have destroyed the spec-08d audit. Instead, `AuditOptions.cortex_config_audit_root: Option<PathBuf>` was added (set to `<workspace>/crates` by `AuditOptions::full()`); `run_audit_with` walks it via `cortex_config::audit()` and emits a `cortex_config` finding (OK when empty, WARN with count when ad-hoc CORTEX_* reads remain) so `/v1/health/config` and `cortex-ops doctor-config` surface ADR-016 §3 migration drift alongside the existing operator checks. 2 new unit tests (empty workspace → OK; synthetic unmigrated call → WARN); all 16 config_audit tests green.
- [ ] 3.4 `cortex-workers/**/*.rs` — every call site migrates. Per-config migration in progress: embedder/config.rs (7 reads → 0), fulltext/config.rs (12 reads → 0), graph/config.rs (12 reads → 0), ingestion/config.rs (5 CORTEX_* reads → 0; SYNAP_URL legacy non-CORTEX read kept as direct env::var fallback per audit ignore rules). 36 ad-hoc env reads removed; remaining `cortex-workers` reads live in bin entry points (`bin/{cortex-consolidator,classifier-worker,fulltext-indexer,graph-writer,graph-backfill,cortex-claude-archive}.rs`) + `classifier_worker/{config,worker}.rs` + `graph/stale_sweeper.rs` + `fulltext/routing.rs` + `claude_archive/tail.rs` — separate per-file commits.
- [x] 3.5 `cortex-cli/**/*.rs` — 78 live CORTEX_* reads across 18 files migrated to `cortex_config::Config`. New Config sub-structs: `DoctorConfig` (bench bool), `ClassifierConfig` (health_url, staleness_ms), `ConsolidatorConfig` (fallback_file), `AutoMemoryConfig` (project). Extensions: DashboardConfig.{api_token, api_url}; IngestionConfig.{ingestion_url, cas_db}; NexusConfig.metadata_db. 10 new KNOWN_ENV_NAMES entries. Helpers in `helpers.rs`, `schedule_cmd.rs`, `cortex-ops.rs` (`resolve_metadata_db_path`/`resolve_db`/`resolve_metadata_path_for_bookkeeping`/`api_keys_db_path`) and per-command helpers (consolidation prune env, doctor probe builders, sessions backfill archive resolver, etc.) now call `cortex_config::Config::load()`. Operator-visible break expands: `CORTEX_DOCTOR_BENCH` now requires literal `true`/`false` (was `1`/`0`). Removed 5 per-helper env-mutation tests that duplicated centralized cortex-config coverage and raced on shared env state (CORTEX_HOME, CORTEX_ARCHIVE_ROOT); env-precedence is now pinned by `crates/cortex-config/src/load.rs::tests`. ## 4. Doctor config-audit
- [x] 4.1 `cortex-ops doctor config-audit` invokes `cortex_config::audit()` and prints the report. New `cortex-ops doctor-config-audit [--crates-root PATH] [--json]` subcommand in `crates/cortex-cli/src/bin/cortex-ops/config_audit.rs`. Resolves the crates root via `--crates-root` flag → walk-up from cwd looking for `crates/`. Renders either a tabular text report (`<path>:<line>  <env_name>` per row, padded for column alignment) or a JSON envelope (`{ crates_root, total, failed, usages: [...] }`).
- [x] 4.2 Exit 0 when zero ad-hoc reads outside the config crate; exit 2 otherwise. Implemented via `ExitCode::SUCCESS` / `ExitCode::from(2)` branches on `envelope.failed`. 2 unit tests in `config_audit::tests` (empty crates root → SUCCESS; ad-hoc read seeded → exit code 2).
