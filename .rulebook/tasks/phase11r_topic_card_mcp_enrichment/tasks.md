## 2. cortex-topic-cards crate

- [x] 2.1 **ADR-007 deviation applied.** The original §2.1 plan called for a new `cortex-topic-cards` workspace member. ADR-007 (committed alongside phase11s) prohibits new top-level crates for worker-style daemons — they live inside `cortex-workers` behind a feature flag (when deps are unique) or unconditionally (when shared). Topic-cards' deps are entirely shared with cortex-workers (chrono, sha2, serde, tokio, async-trait, reqwest already present from the consolidator merge), so the module lands unconditionally at `crates/cortex-workers/src/topic_cards/`. Module declarations: `contradictions`, `orchestrator`, `producer`, `synthesiser`, `templates`, `trigger`, `prelude`. `pub mod topic_cards;` added to `crates/cortex-workers/src/lib.rs` (alphabetical order between `retention` and EOF).
- [x] 2.2 Prompt template at `crates/cortex-workers/templates/topic_cards/rewrite.md` (subdirectory under the existing `templates/` dir that hosts the consolidator session/topic/decision_trace templates). Slots: `{{topic_slug}}`, `{{repo_scope}}`, `{{existing_synthesis}}`, `{{existing_revision}}`, `{{new_evidence_block}}`, `{{superseded_evidence_block}}`, `{{output_contract}}`. Output contract pins `{synthesis_markdown, contradictions, open_questions, confidence}` JSON shape (no `title` field — the topic_slug carries the identity). `templates.rs` exposes `RewriteSlots<'a>` (borrowed strs, zero-copy in the steady state) + `render_rewrite_prompt(slots) -> String` doing `{{key}}` substitution. 3 unit tests pin: substitution of all known slots, unknown-slot fallthrough (typos surface as literal `{{foo}}` so the operator notices), slots round-trip with empty values.
- [x] 2.3 `synthesiser.rs` ships `TopicCardSynthesiser` holding `Arc<dyn cortex_workers::consolidator::summariser::Summariser>` (composition over duplication; no new abstract trait). `rewrite(slots: RewriteSlots<'_>) -> Result<RewriteOutput, SynthesiserError>` renders the template, calls `summariser.summarise()`, strips ```` ```json ```` code fences, deserialises into `RewriteOutput { synthesis_markdown, contradictions: Vec<RawContradiction>, open_questions: Vec<String>, confidence: f32, cost_cents: u32 }`. `RawContradiction` carries `kind` / `evidence_a` / `evidence_b` only — the producer (§2.4) stamps `surfaced_at_rev` and `status: Open`. `SynthesiserError` wraps `SummariserError` plus a `Parse(String)` variant for malformed JSON. 5 unit tests pin parse-success on raw JSON, code-fence-stripped (json + plain ```), missing-field rejection, cost passthrough, summariser-error mapping.
- [x] 2.4 `producer.rs` ships `produce(input: &ProduceInput, synthesiser: &TopicCardSynthesiser) -> Result<ProducedTopicCard, ProducerError>`. `ProduceInput` carries `topic_slug`, `repo_scope`, `existing_card: Option<TopicCardPayload>`, `all_evidence: Vec<EvidenceRef>` (caller pre-dedupes by id — the producer trusts the canonical citation set), `new_evidence_text` / `superseded_evidence_text` (rendered prompt blocks), `force_deep: bool`. Pipeline: build slots → call synthesiser → validate output (synthesis byte range, open_questions count) → enrich raw contradictions with `surfaced_at_rev = next_revision` + `status = Open` → build `TopicCardPayload` with `revision = prior + 1` (or 1 first emit), `events_since_last_rev = 0`, `last_rev_at = now()`, `topic_card_id` via §1.3 helper, `synthesis_model` from `synthesiser.summariser_kind().model_id()`. `ProducerError` enum: `Synthesiser(SynthesiserError)`, `SynthesisBelowFloor`, `SynthesisAboveCeiling`, `InvalidField`. 8 unit tests covering: first-emit revision=1, re-rewrite revision monotonicity, code-fence stripping (json + plain), missing-field rejection, summary-below-floor (199 byte boundary), summary-above-ceiling (4001 byte boundary), idempotent topic_card_id across runs, cost passthrough through the result struct.
- [x] 2.5 `trigger.rs` ships `Trigger::evaluate(card: Option<&TopicCardPayload>, new_event: &EventClassifier, distance: f32, now_rfc3339: &str) -> TriggerDecision`. The original §2.5 brief used `&Envelope`; rebuilt as a small `EventClassifier { kind, is_high_impact }` so the orchestrator can build it upstream with whatever signal makes sense (the Envelope shape carries too many unrelated fields). Constants: `TRIGGER_EVENTS_THRESHOLD = 8`, `TRIGGER_DISTANCE_THRESHOLD = 0.30`, `TRIGGER_AGE_DAYS = 14`. Heuristics return `Rewrite` when `events_since_last_rev >= 8` OR (`distance < 0.30` AND new_event kind is Decision / LawViolation / a high-impact-outcome event) OR `synthesis_age_d >= 14 AND any new evidence`. `Hold { reason: HoldReason }` with `HoldReason ∈ {Cooldown, LowImpact, NotRelevant}` otherwise. 7 unit tests cover every branch (events threshold, distance + Decision, distance + LawViolation, distance + high-impact outcome, stale-age + new evidence, cooldown hold, not-relevant hold).
- [x] 2.6 `contradictions.rs` ships `scan(hydrated: &[HydratedEvidence], at_rev: u32) -> Vec<Contradiction>`. The original §2.6 brief used a hydration callback (`hydrate_fn`); rebuilt as a `HydratedEvidence` value type the caller pre-builds (callbacks complicate the orchestrator's call site without buying anything for the in-memory scan). `EvidenceFacts` enum carries the per-kind facts the detectors need: `Decision { decision_id, supersedes }`, `LawViolation { law_id, law_version }`, `Law { law_id, version, active }`, `Consolidation { temporal_start_ms, temporal_end_ms, outcome_majority }`, `Turn`. Heuristic-only — never blocks rewrite. Each emitted `Contradiction` carries `surfaced_at_rev = at_rev` and `status = Open`. 9 unit tests covering each class accept / reject / edge case (single evidence, no contradictions, mixed kinds).
- [x] 2.7 `orchestrator.rs` ships `Orchestrator::new(haiku, opus)` + `with_budget(CostBudget)` + `run(input: ProduceInput) -> Result<ProducedTopicCard, OrchestratorError>`. `GRAIN_LABEL = "topic_card"` (the cost-ledger grain bucket key).
