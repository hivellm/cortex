## 2. `cortex_similar_sessions` — consolidation vector search
- [x] 2.1 New module `crates/cortex-api/src/similar_sessions.rs`. Inputs: `{ query: String, repo: Option<String>, k: u32 (default 5, max 10), confidence_floor: f32 (default 0.6) }`. Outputs: top-K `ConsolidationHit { consolidation_id, session_id, title, summary_markdown, source_event_count, occurred_at, score }`. (Module ships request/response/filter types, `ConsolidationSearchSource` trait, `VectorLaneConsolidationSource<L: VectorLane>` live impl, `UnwiredConsolidationSource` honest-empty default, `project_hit` LaneHit projection. Score is `f64` to match `LaneHit::score` upstream; the spec's `f32` was a notation slip.)
- [x] 2.2 Embeds `query` via the same path the embedder uses for ingestion (`cortex_workers::embedder::vectorizer_client::LiveVectorizerClient::embed_query`), then searches `cortex-<repo>-consolidations` Vectorizer collection (or all consolidation collections when repo unset) via `vectorizer-sdk::search`. Applies the confidence floor. (Embedding + search go through the existing `VectorLane::search(VectorRequest { collection, query, k, scope })` contract; collection name resolves via `consolidation_collection(repo)` → `cortex-<repo>-consolidations`. Spec deviation: `repo` is REQUIRED in this revision (the cross-repo "all collections" variant is a follow-up that needs the daemon to enumerate indexed repos at request time); handler rejects missing repo with `400 bad_input`.)
- [x] 2.3 Route `POST /v1/search/similar-sessions` on `cortex-api`. Body matches the input shape; response is `Vec<ConsolidationHit>`. (Route mounted via `similar_sessions::build_router` merged into the base router after `with_state(state)`; default state is `SimilarSessionsState::default()` (honest-empty `UnwiredConsolidationSource`) until main.rs threads a live `VectorLane` in. Response shape gains a `{rows, total, filter}` envelope per ADR-014 pure-reader contract — GUI / MCP consumers see the active filter without re-deriving from the request body.)
- [x] 2.4 MCP tool `cortex_similar_sessions` registered alongside the existing `cortex_vector_search`. Cypher gate not applicable (no graph access). Cap K at 10 server-side. (`SimilarSessionsTool` registered, registry count 11 → 12; descriptor declares `query` + `repo` required with `k` (default 5, max 10) and `confidence_floor` (default 0.6) optional; handler rejects `k=0`, `k > 10`, and `confidence_floor` outside `[0.0, 1.0]` BEFORE the HTTP round-trip via `ToolError::invalid_input`; daemon clamps too.)
- [x] 2.5 Unit tests: 5 (empty corpus returns empty Vec, repo filter scopes to one index, confidence floor drops sub-0.6 hits, K cap clamps requests > 10, score is reciprocal-rank-of-distance not raw cosine). (9 module tests + 4 MCP tool tests = 13 new: clamp_k bounds, lowercased collection name, project_hit fallback + extras read paths, empty-source response shape, sort-by-score-then-cap, k > MAX_K clamping, missing-query 400, missing-repo 400, MCP descriptor required fields + k bounds, MCP rejection of k > 10 / k = 0 / floor > 1.0.)

## 3. `cortex_decision_chain` — ADR supersession walker
- [ ] 3.1 New module `crates/cortex-api/src/decision_chain.rs`. Input: `{ event_id: String, max_hops: u32 (default 16) }`. Output: `{ chain: Vec<DecisionNode>, walked_predecessors: u32, walked_successors: u32 }`. `DecisionNode = { event_id, slug, status, date, title, supersedes: Option<event_id>, superseded_by: Option<event_id> }`.
- [ ] 3.2 Cypher walks both directions via `nexus-graph-sdk`: `MATCH (d:Decision { event_id: $id })<-[:SUPERSEDES*0..16]-(pred:Decision)` for predecessors and `(d)-[:SUPERSEDES*0..16]->(succ:Decision)` for successors. Merges results into a single chronological vector by `date`. Cycle-detection: when a node already appears in the result set, the walker stops that branch.
- [ ] 3.3 Route `GET /v1/search/decision-chain?event_id=<id>&max_hops=<n>` on `cortex-api`. Returns the merged chain.
- [ ] 3.4 MCP tool `cortex_decision_chain`. Handler enforces `max_hops <= 16`; rejects `event_id` not matching `[0-9A-Z]{26}` (ULID regex).
- [ ] 3.5 Unit tests: 6 (no-supersession case returns single-node chain, linear chain A->B->C produces 3-node ordered result, fork A<-B, A<-C produces both predecessors, cycle guard breaks loop A->B->A at hop 2, max_hops cap stops walk early, invalid event_id returns 400).
