### Added

- **phase15e — ingestion-time redaction policy (ADR-024).** `cortex-core::redact::PATTERN_CATALOG_V1` exposes 12 compiled patterns (aws_access_key_id, aws_secret_access_key, github_token, slack_token, openai_api_key, anthropic_api_key, google_api_key, stripe_live_key, bearer_token, private_key_pem, jwt, generic_env_secret). `redact(value: &mut Value) -> RedactReport` walks the envelope JSON in-place, replaces each match with `[REDACTED:<class>]`, and returns opaque `secret:<class>:<locator>` tokens for the `envelope.redactions` field. The adapter already calls `redact()` in `events.rs` before dispatching to the ingestion endpoint. ADR-024 (`ingestion-time-redaction-policy`) records the decision to redact at adapter time (before Synap publish) so secrets never reach the embedder, fulltext indexer, graph writer, or archive. New `cortex-ops doctor-redaction-coverage [--synap-url URL] [--stream NAME] [--json]` samples the 100 most-recent envelopes from `cortex.events.raw`, re-runs `PATTERN_CATALOG_V1` against each payload, and reports any `unredacted-candidate` hits (field path + byte offset + 16-char preview + sha256 hash). Exit 0 = clean; exit 2 = at least one candidate found. Spec `docs/specs/01-event-schema.md` updated with PATTERN_CATALOG_V1 table and the operational verification playbook. Tests: 8 unit tests in `crates/cortex-core/tests/redact.rs` (one per pattern class, non-secret false-negative guard). Commit: phase15e §2–§4.

- **phase15d — `cortex-laws` crate (Laws DSL v1).** YAML-based law loader and evaluator. A `Law` carries `id`, `severity` (critical/high/medium/low/info), `trigger` (tool / action / args_match regex — AND logic, all unset fields are wildcards), `rule.verdict` (allow/deny/warn), and `rationale`. `LawRegistry::load(dir)` walks all `.yml` files under the directory, rejects duplicate IDs with a clear error, pre-compiles `args_match` regexes at load time. `LawRegistry::evaluate(ctx)` returns one `Verdict` per matching law. `LawRegistry::empty()` for test/disabled contexts. 13 unit tests including deny/warn/allow fixture paths and error cases (duplicate ID, invalid regex, nonexistent dir). Spec 13 updated: status `v1 Shipped`; Deno sandbox / law CLI / versioning / governance engine integration deferred to future phases — enforcement belongs to adapter / Rulebook, not Cortex core.

- **phase15h — graph-worker offset persistence + `graph seek-head` recovery.** The worker's `consumer_offsets` SQLite DB lived in the ephemeral container FS, so every `docker compose up` recreate re-seeded the cursor at 0 and re-consumed all of `cortex.events.enriched`, re-MERGEing the whole graph in one burst — which repeatedly pinned Nexus 2.3.2 at 100% CPU (nexus#12) during the 2026-06-09 incident. Fixes: (1) bind-mount `./.cortex-state/graph` + `CORTEX_GRAPH_METADATA_DB` so the offset survives recreates — **and** add the missing `CORTEX_GRAPH_METADATA_DB → /nexus/metadata_db` env mapping (it was documented on `NexusConfig.metadata_db` but absent from `env_map`/`KNOWN_ENV_NAMES`, so the worker silently ignored it); (2) new `cortex-ops graph seek-head [--synap --consumer-id --stream --metadata-db --dry-run]` that reads the Synap stream head (`stream.stats.max_offset`) and writes it as the committed offset, so an operator can resume the worker from `head+1` (new events forward) instead of replaying history. Cold-boot default stays start-from-0 (preserving the 2026-05-03 latest-default fix that stopped dropping 12/20 repos); seeking head is an explicit recovery, never automatic. Verified: seeded head, recreated the worker, Nexus held ~1% CPU while the worker resumed at head structural-only. Spec: `docs/specs/07-graph-writer.md` § Offset persistence & recovery.

- **phase15c (graph projection live coverage) — endpoint anchors + projection kill-switch + bounded live-write backfill.** Closes the EMITTED_BY-drops gap: `graph/projection.rs::project_envelope` now appends one empty-props `NodeOp::with_identity` per distinct edge endpoint (deduped, first-seen order → byte-identical re-projection), so edges to labels the mapper never mints (`Tool[tool_name]` / `Model[model]`, or a `Decision`/`Evidence` outside the batch) MATCH at the writer instead of silently dropping — verified by the bounded backfill (29,626 EMITTED_BY projected / 0 persisted pre-fix → 481/481 persisted post-fix, with real `Tool[Bash/Edit/Read/…]` anchors). `cortex-ops graph backfill` gains `--apply --limit <N> [--nexus <url>]` to write a bounded archived-envelope window through the real `GraphWriter` (chunked 256/tx). **Graph-writer Nexus-2.3.2 fixes uncovered by exercising the edge-write path** (which the idle live worker had never hit): `render_edge_merge` inlines props into the MERGE pattern (Nexus rejects `r` in any SET clause; volatile `created_at_ms` excluded for idempotency) and the soft-drop guard now also catches endpoint-missing "no rows" so a missing endpoint no longer aborts the batch. **Operational kill-switch** `CORTEX_GRAPH_PROJECTION_ENABLED` (`NexusConfig.projection_enabled`, default `true`) gates the worker's projection pass — the anchor + per-edge write volume trips Nexus 2.3.2's sustained-write stall (nexus#12) on a backlog-drain burst, so it ships **`false` in docker-compose** (worker structural-mapping-only) until Nexus is upgraded. - **phase12b — bulk Parquet archive purge + cron sweep.** Operators in production were running `rm -rf` on the archive directory because `cortex-api`'s `/v1/admin/forget` per-event surface was unusably slow at scale; both 4-doc and opus5.7 analyses flagged this as the root cause of "memory cleanup has to be brute force". Closed in this rev: (1) New module [`crates/cortex-storage/src/archive_purge.rs`](crates/cortex-storage/src/archive_purge.rs) exposing `purge_before(home, cutoff, dry_run, repo_filter) -> Result<PurgeReport>`. Walks `${home}/events/year=YYYY/month=MM/day=DD/hour=HH/*.parquet`, deletes every file whose newest envelope's `occurred_at` is strictly older than `cutoff`. Honours the live-frame guard (mirrors `cortex-api::admin_forget::is_live_partial_frame`) so the current-hour file the writer is still flushing is preserved. Conservative repo-filter shape: a file mixing the named repo with others is kept (deleting it would orphan the surviving rows). (2) New CLI subcommand `cortex-ops retention-archive-purge --before <RFC3339> [--dry-run] [--repo <slug>] [--home <path>]` prints the JSON report; exit `0` when every file was either kept or deleted cleanly, `2` on partial failure (per-file delete error / cutoff parse / unresolvable home / unreadable file). (3) New `retention.archive_purge` cron seed in `cortex-workers::retention::scheduler::default_jobs` at `15 3 * * *` (15 min offset from `retention.consolidation_prune` to avoid minute-level contention; the proposal's literal `0 3 * * *` was a conflict). (4) Sweep handler writes one `retention_sweeps` row per invocation with the full `PurgeReport` in `tier_transitions_json` so the dashboard's retention card surfaces the run alongside every other sweep. Tests: 6 in storage walker (no archive / all old / mixed / partial-frame guard / dry-run / repo filter), 5 IT in `cortex-cli::tests::archive_purge_cli_it` (gated on `not(debug_assertions)` because `cortex-ops` debug binary on Windows overflows the default main-thread stack), 3 helpers (resolve_home cascade), seed-count assertion bumped 11 → 12.

- **phase12f — `record_cron_run` TOCTOU race fixed.** [`crates/cortex-storage/src/metadata.rs::record_cron_run`](crates/cortex-storage/src/metadata.rs) used to do `SELECT failure_streak` then `UPDATE … failure_streak = ?` — two read-modify-write round-trips. Two cron supervisors (multi-replica deploy or restart-overlap) racing on the same job both read the same `streak`, both compute `streak+1`, both UPDATE — net advance of 1 instead of 2, lost increments scaling with contention. Closed in this rev: collapsed to a single `UPDATE … SET failure_streak = CASE WHEN ?2 = 'failed' THEN failure_streak + 1 ELSE 0 END … WHERE name = ?7 RETURNING failure_streak` statement. SQLite's WAL writer-lock + the workspace's `busy_timeout` PRAGMA serialise concurrent writers automatically — a single-statement UPDATE is atomic by construction so the explicit `BEGIN IMMEDIATE` the proposal anticipated is unnecessary. Three new tests in `metadata::tests`: single-thread happy path (failed → 1 → 2 → success → 0), all-failures concurrency (4 threads × 250 calls = 1000 increments observed exactly), mixed-status concurrency (alternating fail/success across 4 threads × 100 calls). Tests run under `--release` to expose timing-dependent races the debug build's slower instruction stream would mask. The new path is also faster than the legacy path: one round-trip + one prepared statement + one write lock vs two of each.

- **phase12e — `KIND_IDS` complete + compile-time enum guard.** `crates/cortex-core/src/vocab.rs::KIND_IDS` had only 8 of the 12 `Kind` variants (`turn`, `tool_call`, `agent_call`, `memory`, `decision`, `analysis`, `law_violation`, `artifact`); the four kinds added in phase10e (`knowledge`, `learning`) and phase11j/r (`consolidation`, `topic_card`) were never appended. The vocab is the runtime check the ingestion router uses against `envelope.schema.json`'s string enum — a missing entry is a silent-data-loss bug (envelope rejected, INFO-level "unknown kind" nobody monitors). Closed in this rev: (1) all four stems appended to `KIND_IDS`; (2) new `Kind::COUNT = 12` constant on the enum; (3) compile-time `const _: () = assert!(KIND_IDS.len() == Kind::COUNT, "…");` guard in [`vocab.rs`](crates/cortex-core/src/vocab.rs) so adding a `Kind` variant without an `KIND_IDS` entry fails `cargo check` with an actionable message instead of failing silently at ingest; (4) round-trip tests `every_kind_round_trips_through_kind_ids` + `kind_ids_has_no_duplicates` pin forward / reverse mapping, count match, and uniqueness. The proposal's §2 miss-counter is moot by construction — the closed enum + compile-time guard rule out a runtime miss path; implementing a counter that can never increment is the "error handling for impossible scenarios" anti-pattern.

- **phase11s — workers consolidation merge.** Folded five sibling crates (`cortex-classifier`, `cortex-ingestion`, `cortex-claude-archive`, `cortex-consolidator`, `cortex-retention`) into `cortex-workers` as modules under `src/<area>/`. Workspace member count: **14 → 9**. Bin names preserved on the operator-facing surface. Heavy claude-archive deps (`indicatif`, `sysinfo`, `ignore`) gated behind a new `claude-archive` Cargo feature (default OFF); other merged areas link unconditionally because their deps were already shared with workers. New operator bin `cortex-retention-sweep` pins the systemd / docker bin-name slot for the tier-transition sweep (dry-run-only today; `cortex-ops sweep` continues to host the live LiveVectorizerOps adapter until a follow-up task lifts it). The duplicate `cortex-consolidator` bin (one in `cortex-cli`, one in `cortex-consolidator`) was reconciled into a single unified bin under `cortex-workers/src/bin/cortex-consolidator.rs` exposing all 5 subcommands (`estimate` + `run-session` + `run-topic` + `run-decision` + `nightly`). See [ADR-007](.rulebook/decisions/007-cortex-workers-as-the-default-host-for-worker-style-daemons.md) and [`docs/cortex/workers-modules.md`](docs/cortex/workers-modules.md) for the module → bin map.
