# Tml — Cortex Relevance

## Why Tml Matters for Cortex

Tml serves three critical roles in the HiveLLM ecosystem:

1. **Compilation target**: Code generated by AI (via Cortex or Claude) can be compiled and executed deterministically
2. **Semantic search source**: Tml's stdlib documentation (6000+ items) provides a high-quality reference corpus for Cortex indexing
3. **LLM-friendly syntax**: LL(1) grammar + self-documenting keywords reduce LLM code generation errors

## Ingestion Priorities for Cortex

### Priority 1: Tml Standard Library Documentation

**What to index**: All public APIs in `lib/core` and `lib/std`

- **6000+ items**: Functions, types, behaviors (traits), constants
- **3 formats**: HTML (human), JSON (machine), Markdown (GitHub)
- **Search tool**: `mcp__tml__docs/search` provides hybrid BM25 + HNSW queries

**Cortex action**:
1. Run `tml doc lib/ --format=json` to extract API schema
2. Index into Meili (lexical search) + Vectorizer (semantic embeddings)
3. Configure walker to re-extract on each Tml release

**Benefit**: Cortex can answer questions like "How do I send data on a channel?" with exact API matches + ranked by relevance.

### Priority 2: Tml Source Files (`.tml`)

**What to index**: All `.tml` source files in bootstrap projects

**Walker support**: Already enabled in `7fd3c62` (feat: index .tml files)

**Cortex action**:
1. Configure walker to extract `.tml` files from HiveLLM repos
2. Run `mcp__tml__check` on each file to extract type signatures
3. Extract AST or HIR for structural search (find all functions returning `I32`, etc.)

**Benefit**: Enables "find examples of X pattern" queries (e.g., "Show me a channel send + recv pattern").

### Priority 3: Tml Compiler Diagnostics

**What to index**: Error messages, warnings, hints from `mcp__tml__check` and `mcp__tml__lint`

**Cortex action**:
1. When AI generates invalid Tml code, capture error message
2. Index: `(code snippet, error, suggested fix)`
3. Build feedback loop for LLM fine-tuning

**Benefit**: Over time, Cortex learns which Tml constructs LLMs hallucinate and can provide context to avoid them.

## Integration Points

### 1. Walker → Tml Documentation

```
Walker discovers .tml files
    ↓
Runs `mcp__tml__check` to validate
    ↓
Runs `tml doc` to extract API signatures
    ↓
Cortex ingests into Meili + Vectorizer
```

### 2. API-Server → Code Generation

```
User asks: "Generate TML HTTP server"
    ↓
Cortex queries walker index for patterns
    ↓
Retrieves examples + API docs for `std::http`
    ↓
LLM generates code with context
    ↓
Cortex validates via `mcp__tml__check`
```

### 3. Validator → Tml MCP Tools

```
Generated TML code
    ↓
`mcp__tml__check` (fast type-check)
    ↓
`mcp__tml__lint` (semantic analysis)
    ↓
`mcp__tml__test` (if test suite provided)
    ↓
Report errors to LLM for refinement
```

## Security Considerations

- **No external network access** required for compilation
- **Deterministic builds**: Same source + compiler = same binary (important for reproducibility)
- **MCP server** runs via stdio; no network exposure
- **Borrow checker** prevents use-after-free, buffer overflows at compile-time

Safe to run in Cortex containers without additional sandboxing.
