# Tml — Open Questions & Gaps

## Implementation Gaps

### Package Management
- **Status**: Not implemented
- **Question**: Will Tml projects in Cortex need external dependencies beyond stdlib?
- **Impact**: Currently, all 150K+ lines of functionality are built-in. Package management deferred.
- **Cortex implication**: For now, assume Tml runs standalone (no external crates).

### Language Server Protocol (LSP)
- **Status**: Partial (VSCode extension via `vscode-tml`)
- **Question**: Does Cortex need LSP for incremental validation, or is MCP sufficient?
- **Impact**: MCP tools (`check`, `lint`, `format`) cover all Cortex needs; LSP is IDE-only.
- **Cortex implication**: MCP is the integration point, not LSP.

### Self-Hosted Compiler
- **Status**: Active development on `feat/self-hosting-compiler` branch
- **Question**: When will Tml compile itself?
- **Impact**: Currently C++20 compiler is stable; self-hosted is aspirational.
- **Cortex implication**: ZERO impact. Use C++ compiler indefinitely.

## Semantic Gaps

### Documentation Search Semantics
- **Status**: Implemented (BM25 + HNSW)
- **Question**: Does it handle domain-specific synonyms well? (e.g., "async send" → `Channel::send`)
- **Impact**: Search quality is critical for AI code generation. 65+ synonyms are hardcoded; may need tuning per domain.
- **Cortex action**: Test with representative queries; capture low-confidence results for fine-tuning.

### FFI to Hive Services
- **Status**: C FFI implemented; Hive SDK bindings NOT done
- **Question**: How to call Vectorizer, Nexus, Synap from TML?
- **Impact**: Currently no official Tml SDKs for Hive services.
- **Cortex action**: If needed, define minimal C bindings. Otherwise, call via HTTP from stdlib `http` module.

## Maturity Questions

### Stdlib Coverage
- **Status**: ~40 modules, 99% function coverage
- **Question**: Are there gaps in domain-specific areas (e.g., ML libraries, GPU)?
- **Impact**: Stdlib is **general-purpose**, not AI-specialized.
- **Cortex action**: If TML is used for worker logic, current stdlib suffices.

### Compiler Stability
- **Status**: "100% functional (beta)" — all features implemented, 12K+ tests pass
- **Question**: What does "beta" mean? Known issues?
- **Impact**: Likely stable for production; "beta" = user-facing APIs may evolve.
- **Cortex action**: Assume stable; treat as production-grade.

### Cross-Platform Testing
- **Status**: Builds on Windows (Zig/MSVC/Clang), Linux (GCC/Clang), macOS
- **Question**: Are all features tested equally on all platforms?
- **Impact**: CI/CD likely focuses on Windows (where project originates).
- **Cortex action**: Test Tml workers on Linux (Cortex's deployment platform).

## Operational Questions

### Docker Deployment
- **Status**: Tml can be containerized (single binary)
- **Question**: Are there official Cortex Tml worker Docker images?
- **Impact**: Currently unknown; Cortex may need to build its own.
- **Cortex action**: Define Dockerfile pattern for Tml workers.

### Daemon Lifecycle
- **Status**: `tml daemon start|stop` commands exist
- **Question**: How to manage daemon in multi-worker scenarios?
- **Impact**: Daemon improves rebuild speed (22ms cached), but adds process management complexity.
- **Cortex action**: Evaluate cost/benefit; probably use stateless builds instead.

### Concurrent Compilation
- **Status**: Parallel test execution (subprocess model), but module-level parallelism unclear
- **Question**: Can Tml compile multiple modules in parallel?
- **Impact**: For large projects, sequential compilation is a bottleneck.
- **Cortex action**: Profile compile times; request feature if needed.
