# 13 — Laws DSL + detector contract

> **Status:** 🟡 Draft · **Owner:** Core team · **Depends on:** 01, 04

## Goal

Define the on-disk representation of a **Law** (YAML frontmatter + Markdown body), the **detector contract** (a small sandboxed TypeScript function that inspects an event and returns `{violated, evidence}`), the loader/validator, and the registry that the adapters + governance engine (spec 14) consume. A Law without a detector is a Markdown file. A detector without a Law is dead code. This spec is what makes the two inseparable.

## Scope

**In:**
- `cortex-laws` crate: loader, validator, detector sandbox, registry.
- File format: `laws/<area>/<id>.md` with YAML frontmatter.
- Detector execution sandbox (Deno / Node with strict no-network / no-fs / bounded CPU & memory).
- Two execution modes: **blocking** (synchronous, `PreToolUse`, ≤100 ms) and **observational** (async, post-event).
- Versioning + supersession.
- Law CLI (`cortex laws lint`, `cortex laws list`, `cortex laws test`).
- Registry export API for adapters/governance engine.

**Out:**
- Enforcement / punishment (spec 14).
- Human authoring UX (dashboard view — spec 16).
- Bulk import from existing rule files (handled by spec 09 `law.imported` events).
- Distributed detector execution (single-node in v1).

## Inputs / Outputs

### File layout

laws/
├─ git/
│  ├─ LAW-007.md                           # "Never pass --no-verify"
│  └─ LAW-015.md

### Law file

```markdown
---
id: LAW-007
title: Never bypass pre-commit hooks
version: 2                                  # monotonic; bumps require supersession
severity: critical                          # info | notable | critical
mode: blocking                              # blocking | observational
applies_to:                                 # event selector (matches envelope fields)
  kinds: [tool_call.requested]
  tools:  [Bash]
  scopes: ["*"]                              # repo filter; glob
detector:
  runtime: deno
  entry: detectors/law-007.ts
  timeout_ms: 80                             # <100 for blocking laws
remediation: |
  Fix the hook failure directly; do not pass `--no-verify`.
  If the hook itself is broken, open an issue before committing.
introduced: 2026-04-17
supersedes: null
tags: [git, safety]
---

# LAW-007 — Never bypass pre-commit hooks

The model MUST NOT pass `--no-verify` to `git commit` or `git push` unless the user has explicitly
authorized it in this session.

## Rationale

Pre-commit hooks enforce quality gates. Skipping them is how we introduce the kind of regression
that costs us a day of debugging for three characters of typing.

## Evidence format

The detector returns `{ violated: true, evidence: { command: "git commit --no-verify -m ...",
  tool_call_id: "..." } }`.
```

### Detector contract (TypeScript)

```typescript
// detectors/law-007.ts
import type { DetectorInput, DetectorOutput } from "cortex:detectors";

export default function detect(input: DetectorInput): DetectorOutput {
    if (input.event.kind !== "tool_call.requested") return { violated: false };
    if (input.event.payload?.tool_name !== "Bash") return { violated: false };

    const cmd = input.event.payload?.input?.command ?? "";
    const bypass = /git\s+(commit|push)\b[^&|;]*--no-verify\b/.test(cmd);
    if (!bypass) return { violated: false };

    const authorized = input.session.authorizations?.some(
        (a) => a.matches?.includes("git_no_verify")
    );
    if (authorized) return { violated: false };

    return {
        violated: true,
        evidence: { command: cmd, tool_call_id: input.event.tool_call_id },
        message: "LAW-007: --no-verify is not authorized in this session.",
    };
}
```

### Detector input / output

```typescript
export interface DetectorInput {
    event: EnvelopeEvent;                     // spec 01 envelope (read-only)
    session: {
        session_id: string;
        started_at: number;
        authorizations: Array<{ matches: string[]; granted_at: number }>;
    };
    context: {
        repo: string | null;
        recent_violations: Array<{ law_id: string; ts: number }>;
    };
}

export interface DetectorOutput {
    violated: boolean;
    evidence?: Record<string, unknown>;         // serialisable; stored verbatim
    message?: string;                            // user-facing one-liner
    suggest_remediation?: string;                // optional override of the law's remediation
}
```

## Design

### Detector sandbox

- **Runtime:** Deno, embedded via `deno_core`. No `--allow-net`, no `--allow-read`, no `--allow-write`, no `--allow-run`, no `--allow-env`. Permissions locked at spawn.
- **CPU cap:** V8 `terminate_execution` after `timeout_ms` (law-declared, capped at 100 ms for blocking, 2 000 ms for observational).
- **Memory cap:** 32 MB per detector invocation.
- **Pool:** warm worker pool of N=4 detector workers; each reused round-robin. Workers are recycled after 1 000 executions (protection against leak / slowdown).
- **Panic isolation:** a crashing worker is replaced; no pool-wide failure.

Detectors are **pure** — the sandbox guarantees they cannot mutate external state. Every side-effect (logging, metrics, violation storage) is owned by the Rust host, not the detector.

### Evaluation paths

**Blocking** (spec 10 `PreToolUse` sync path, spec 14 enforcement):

```
event ──▶ SelectorIndex.match() ──▶ [candidate laws]
                                      │
                                      ▼
                          parallel detector evals  (bounded by worker pool)
                                      │
                                      ▼
                           collect: any violated? ──▶ return Violation[]
```

End-to-end budget ≤200 ms (adapter hook budget is 300 ms; leaving 100 ms for network).

**Observational** (post-event workers, async):

- Consumes `cortex.events.enriched` (so it has classifier output).
- Runs every matching detector whose `mode=observational`.
- Emits `cortex.events.law_violation` for each positive result → graph writer (spec 07) + governance engine (spec 14).

### `SelectorIndex`

Pre-built in memory at registry load:

- `kinds`: `HashMap<Kind, Vec<LawId>>`
- `tools`: `HashMap<ToolName, Vec<LawId>>`
- `scopes`: list of `(glob, LawId)` pairs evaluated against `event.context_repo`

Candidate set per event = intersection. Zero-candidate events skip the detector pool entirely — the common case.

### Validation (`cortex laws lint`)

Rejects load-time:

- Duplicate `id` across files.
- Missing `detector.entry` file.
- Detector has TypeScript compile errors (runs `deno check`).
- Detector returns non-object / wrong shape (runs with a synthetic "safe" event).
- `severity: critical` with `mode: observational` (critical must be enforceable).
- `mode: blocking` with `timeout_ms > 100`.
- `version` decreased from `supersedes` target.
- Circular `supersedes` chains.

Warns (but does not reject):

- `applies_to` that matches nothing in the known `Kind` vocabulary.
- `remediation` shorter than 20 chars (poor UX).

Lint output is machine-readable JSON + human-readable text.

### Versioning & supersession

- `version` is monotonic per `id`; bumping requires the new file to declare `supersedes: LAW-007@v1` (existing file kept for audit; registry only serves the newest version).
- Supersession is **additive in Nexus** — old `Law` nodes remain, a new `SUPERSEDES` edge connects them.
- An active `Session` pins the registry snapshot at its start; same session keeps same Laws even if a hot-reload lands mid-session.

### Hot reload

- `cortex laws reload` triggers a rebuild from disk.
- New sessions immediately pick up the new registry.
- Live sessions stay on their pinned snapshot until `Stop`.
- Failed reload → old registry stays; error returned to the CLI.

### Event-selector glob

Scope glob syntax (simple):

```
"*"                → any repo
"Vectorizer"       → exact
"Vectorizer/src/index/**"  → prefix + globstar (Nexus path prefix)
"!Secrets"         → negation (still has to match another positive pattern first)
```

Evaluated left-to-right.

### Built-in detector helpers

Published as a small TS module `cortex:detectors`:

```typescript
export const re = {
    gitBypass: /git\s+(commit|push)\b[^&|;]*--no-verify\b/,
    secretPrefix: /\b(sk_live_|AKIA|ghp_)[A-Za-z0-9]{16,}/,
};

export function touchedFile(event: EnvelopeEvent, globs: string[]): boolean { ... }
export function matchesTopic(event: EnvelopeEvent, topic: string): boolean { ... }
```

Keeps detectors terse and DRY without requiring arbitrary imports (sandbox limits disallow them anyway).

### Failure modes

| Failure                               | Handling                                                                |
|---------------------------------------|-------------------------------------------------------------------------|
| Detector throws                       | `violated=false`; metric `detector.errors`; worker recycled              |
| Detector timeout                      | `violated=false` in blocking mode (fail-open); observational mode retries once |
| Detector returns malformed JSON       | `violated=false`; metric bump                                            |
| Registry load failure                 | Startup aborts; no partial-law registry served                          |
| Selector index miss (event w/ unknown kind) | Event skipped; counter `laws.unknown_kind`                         |
| Sandbox escape attempt (OOM, infinite loop) | Worker killed; replacement spawned; violation evidence records the detector_id as failing |

## Acceptance criteria

- [ ] Empty `laws/` directory loads cleanly; registry has 0 laws; `evaluate_*` return `[]`.
- [ ] A well-formed LAW-007 with a passing detector: synthetic `Bash git commit --no-verify` event → 1 Violation; synthetic `Bash git commit` (no flag) → 0.
- [ ] Blocking-mode latency ≤100 ms P95 on a 16-core dev machine with pool N=4.
- [ ] Observational mode runs on `cortex.events.enriched`, emits `cortex.events.law_violation` for positives (verified via Synap subscriber).
- [ ] `cortex laws lint laws/` rejects: duplicate id; missing detector; mode=blocking with timeout_ms=150; severity=critical with mode=observational. Exit 0 on a clean corpus.
- [ ] Detector sandbox: a detector attempting `fetch()` fails with a permission error; Cortex records `detector.errors{reason=permission}`; violation not emitted.
- [ ] Detector sandbox: a detector with `while(true){}` is terminated at `timeout_ms`; worker recycled; pool stays healthy.
- [ ] Hot reload: modifying `laws/git/LAW-007.md` then `cortex laws reload` installs the new version; existing session still uses the old; a fresh session picks up the new.
- [ ] Supersession: `LAW-007@v2` with `supersedes: LAW-007@v1` makes the old version inactive for evaluation; both remain in the registry index for audit.
- [ ] Selector index: a 1 000-law corpus with selective kinds → per-event candidate set is typically ≤3 (histogram P95 ≤ 5).
- [ ] Scope glob: `applies_to.scopes: ["Vectorizer/src/**"]` matches events with `context_repo=Vectorizer, path=src/x.rs` but not `docs/x.md`.
- [ ] Session pinning: hot-reload mid-session doesn't change which laws are evaluated for the running session.
- [ ] Telemetry counters non-zero after a synthetic soak.

## Decisions

1. **Deno, not a JS interpreter we build.** Deno's permission model is production-grade; writing our own is a rabbit hole.
2. **Detectors are pure.** All side effects live in Rust. Makes detectors testable with a pinned `DetectorInput` and impossible to weaponize.
3. **Critical = blocking, observational ≠ critical.** Enforced by the linter. Critical without enforceability is misleading.
4. **Session pinning.** Changing the rules of the game mid-session breaks user expectations and produces weird audit trails.
5. **Supersession is additive.** Never rewrite history. Old versions stay visible for audit.
6. **Selector index, not brute-force match.** A modest 1 000-law corpus would otherwise cost ≈1 ms per event just on filtering.
7. **Evidence JSON is authoritative.** Detectors decide what evidence to include. The host doesn't second-guess — it stores and displays.

## Open questions

1. **Cross-event detectors.** Some laws need a history window (e.g., "10 failed tests in a row"). v1 only exposes per-event detection. Multi-event detectors will come from a materialized-view layer in spec 14 — tracked there.
2. **Detector language plurality.** Python/Rust detectors? Deferred; TypeScript covers 100% of day-1 needs and the sandbox story is solved.
3. **Authorization scopes richer than keyword match.** Today a session can carry `authorizations: [{matches: ["git_no_verify"]}]`. Finer scopes (path-bounded, time-boxed) are a future extension; the schema is intentionally open for it.
