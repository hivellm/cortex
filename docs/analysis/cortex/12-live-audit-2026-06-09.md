## Bug #1 — CRITICAL: 100% of agent_call events are silently dropped

**Evidence (ingestion logs):**
```
ingest_batch rejected envelope kind=agent_call
  /payload/description: "" is shorter than 1 character
```

**What happens:** The adapter builds `agent_call` envelopes on SubagentStop, but when `description` is empty (`""`), JSON Schema validation rejects the envelope. Adapter health confirms: `envelopes_publish_fail_total.agent_call = 27` — **100% failure rate**.

**Impact:** Zero sub-agent calls are recorded in the knowledge base. All parallel agent activity (researcher, implementer, tester) is invisible to Cortex.

**Fix:** In `cortex-adapter-claude-code`, use a default value when description is empty:
```rust
description: if description.is_empty() { "agent call" } else { description }
```
Or relax the schema: change `minLength: 1` to `minLength: 0` in the agent_call payload definition.

## Bug #2 — CRITICAL: False divergence alert poisons the dashboard and spams ingestion logs

**Evidence (divergence endpoint):**
```json
{
  "pair": "adapter.publish_ok.tool_call -> ingestion.archived.tool_call",
  "upstream": 3593,
  "downstream": 0,
  "severity": "critical"
}
```
**But** the ingestion health endpoint shows `events_archived_total.tool_call = 1,119`.

**What happens:** The divergence checker reads `ingestion.archived.tool_call` from a KV key or registry that the ingestion service never writes to. The downstream always reads `0` — 100% artificial divergence.

**Secondary critical impact:** The checker attempts to record the divergence by posting a synthetic `law_violation` event to ingestion with a malformed event ID (`01ALERT2026060617020298325`, not a valid ULID) and a malformed session ID. Validation rejects it every time, but it floods ingestion logs with noise.

**Evidence (ingestion logs):**
```
ingest_batch rejected envelope event_id="01ALERT2026060617020298325" kind=law_violation
  /event_id: does not match ULID pattern
  /session_id: "01SILENTDROPadapter.publis" does not match ULID pattern
  /tool: "cortex-api" is not one of "claude-code", "cursor" ...
  /payload/law_id: "silent-drop:adapter.publish_ok.tool_call -> ..."
```

**Fix:**
1. Ingestion must publish `ingestion.archived.{kind}` counters to the location the divergence checker reads from.
2. The divergence checker must use a real ULID when generating alert events, or drop the self-reporting mechanism entirely and use a separate out-of-band alert channel.

## Bug #3 — Embedder: 53% error rate is mostly false positives — two distinct causes

**Evidence (embedder logs):**

**Cause A — HTTP 409 Conflict (collection_already_exists):**
```
vectorizer_error detail=HTTP 409 Conflict:
  {"error_type":"collection_already_exists",
   "message":"Collection already exists: cortex-csharp-consolidations"}
```
The embedder calls `create_collection` every time it processes the first chunk of a new collection type. If the collection already exists (created during bootstrap), it gets a 409 — which the embedder counts as an error.

**Cause B — HTTP 401 Unauthorized (expired JWT):**
```
vectorizer_error detail=HTTP 401 Unauthorized: Authentication required
```
Occurs on startup before the first JWT refresh, and in occasional spikes where the token expires before the auto-refresh fires.

**Impact:** Most of the 1,099 errors are benign (409 = idempotent success, 401 = transient). But the inflated counter masks real failures. Health reports `chunks_written_total=2,058` and `vectorizer_errors_total=1,099` with no breakdown by error type.

**Fix:**
- 409 Conflict on `create_collection` must return `Ok(())`, not `Err(...)` — it is an idempotent operation.
- Split the counter: `vectorizer_errors_total{type="conflict"}` vs `{type="auth"}` vs `{type="failure"}`.

## Bug #4 — Classifier running in `Static` mode, not `disabled`

**Evidence:**
- `.env`: `CORTEX_CLASSIFIER_MODE=disabled`
- Container logs: `mode: Static, workers: 2, batch_size: 32`

The docker-compose either ignores the env var or the container was started with a different override. The result: only static regex rules are applied — no LLM calls, no real topics, no summaries, no entity extraction.

**Direct impact on retrieval quality:**
- All events have `topics: []` or shallow generic topics like `["code", "governance"]`.
- No event has a `summary` field — semantic search operates on raw JSON instead of descriptive text.
- Classifier cost today: **$0.00** (confirms zero LLM calls are being made).

**Fix:** Identify which docker-compose or env override is shadowing `CORTEX_CLASSIFIER_MODE`. If the intent is to stay on Static, update the `.env` comment to reflect that. If LLM classification is desired, remove the override.

## Bug #5 — Law definitions are indexed as `law_violation`

**Evidence (Meilisearch cortex_laws index):**
```json
{
  "kind": "law_violation",
  "body": "# Check before test (diagnostic-first)\n\nAlways run diagnostic tools...",
  "detector": null,
  "law_id": "DIAGNOSTIC-FIRST",
  "severity": "info"
}
```

The bootstrap promotes `.claude/rules/*.md` files with `kind: "law_violation"` when they should use `kind: "law"`. As a result, 240 law definition documents appear as violations. The dashboard overview reports `law_violation: 3,332` — the vast majority of these are **law definitions, not incidents**.

**Impact:**
- The dashboard "Law Violations" count is meaningless — it inflates on every bootstrap run.
- Queries for `law_violation` return rule text, not actual breach records.
- The trust score (when implemented) will be distorted from the start.

**Fix:** In the bootstrap, when promoting rule files (`*.md` under `.claude/rules/`), emit `kind: "law"` not `"law_violation"`.

## Bug #6 — Fulltext worker: 85% skip rate on live stream

**Evidence (fulltext worker health):**
```json
"documents_total": 182,
"skipped_empty_total": 1064
```

85% of events arriving at the fulltext worker from the live Synap stream are discarded as `skipped_empty`. The Meilisearch index has hundreds of thousands of documents populated via bootstrap — so the worker itself is functional, but it fails to extract indexable text from most live events.

**Likely cause:** The worker extracts a specific field (e.g., `payload.summary` or `payload.text`) that is empty for most live events. Since the classifier is running in Static mode and produces no summaries, those fields stay empty.

**Fix:** Add a fallback extraction chain in the fulltext worker: try `summary` → `payload` JSON stringified → `kind`+`path` as a minimal document. Never emit `skipped_empty` for a non-empty envelope.

## Bug #7 — frames→envelopes divergence "critical" is a false positive

**Evidence (divergence endpoint):**
```json
{
  "pair": "adapter.frames_parsed -> adapter.envelopes_built",
  "upstream": 7713,
  "downstream": 3999,
  "delta": 3714,
  "severity": "critical"
}
```

**What actually happens:**
- `frames_parsed` includes **PreToolUse (3,695) + UserPromptSubmit (188)** = 3,883 frames that are **by design not converted to envelopes**
- PreToolUse triggers pre-thinking, it does not capture an event
- UserPromptSubmit is UI monitoring, not capture

So 7,713 frames → 3,999 envelopes is the **correct 52% ratio**.

**Fix:** Exclude `PreToolUse` and `UserPromptSubmit` from the upstream counter of this divergence pair, or document the expected ~52% ratio as the threshold instead of treating it as a 1:1 expectation.

## Bug #8 — Retrieval quality: vector scores are too low to be useful

**Evidence (live query results):**

Query: `"event classification system"` (repo: cortex)
```
Rank 1: keyword  score=0.297  → temporal_audit_it.rs (correct)
Rank 2: vector   score=0.130  → test file with FixedTokenBackend stub
Rank 3: vector   score=0.129  → test file with graph_writer stub
```

Query: `"deploy process and release workflow"` (repo: ar-v1-documentacao)
```
Rank 1: keyword  score=0.142  → JSON: {"file_path": "docker-compose-prod.yml"}
Rank 2: vector   score=0.073  → raw tool_call JSON with bash command
```

**Problems:**
1. **Vector scores below 0.15** for natural-language queries indicate the embedded chunks are not semantically close to the query. The `nomic-embed-text-v1.5` (384-dim) model is embedding raw JSON payloads — not human-readable descriptions.
2. **Top results are raw tool_call payloads** (bash commands, JSON objects) — noise, not signal.
3. **Keyword rank 1 returns a file path JSON object** — not useful without surrounding context.
4. **Root cause:** classifier in Static mode → no summaries generated → embedder indexes raw JSON → cosine similarity is low for natural-language queries.

**Fix:** Re-enable classifier with at least Static-with-summaries mode (or LLM mode) so that the `summary` field is populated. Then trigger a re-embed of existing events where `summary` is missing.

## Bug #9 — Pre-thinking latency is degrading

**Evidence (dashboard overview, `pre_thinking_p95_ms` series):**
```
[104, 109, null×12, 813, 837, 875, 1043]
```

p95 went from 104ms to 1,043ms across the last ~20 data points. The circuit breaker budget cap is 800ms — p95 has already exceeded the cap and is still rising.

**Likely causes:**
1. Growing index size without efficient pagination (more docs = slower queries per bundle assembly).
2. No bundle caching — every pre-thinking call is a cache miss (confirmed: `"cache": "miss"` on every tested query).
3. 8+ repos × multiple kinds = many parallel sub-queries per bundle.

**Impact:** When p95 > 800ms, pre-thinking bundles start getting truncated by the circuit breaker. The model receives incomplete context on every turn.

**Fix:** Implement bundle-level caching keyed on `(query_hash, scope, intent)` with a short TTL (30–60s). This alone should drop p95 below 200ms for repeated or similar queries within a session.

## Bug #10 — All 170 decisions carry status "proposed" permanently

**Evidence (dashboard/decisions API):** Every decision returned has `"status": "proposed"`. The ADR-001 rationale text explicitly says "**SUPERSEDED** in round 7" — but the Meilisearch document still shows `"status": "proposed"`.

**Cause:** The bootstrap promotes decisions using a default status, and does not re-read the status when the ADR file is updated. Once promoted as "proposed", the status never changes even as the file evolves.

**Fix:** During bootstrap (incremental or full), re-parse the `**Status**:` line from each ADR markdown file and update the Meilisearch document if the status has changed.
